# Daisson Tunnel Manager — دليل التشغيل

برنامج .NET 8 لويندوز 64 بت. النسخة المنشورة مستقلة ولا تحتاج تثبيت .NET. إعدادات العميل تبدأ فارغة لتستخدم أي دومين وأي حساب Cloudflare. لا يوجد حساب أو توكن مضمّن.

## أول مرة لدومينك daisson.tech

1. أضف `daisson.tech` إلى حسابك في [Cloudflare](https://dash.cloudflare.com/). يمكن بقاء تسجيل الدومين وتجديده في Hostinger.
2. راجع سجلات DNS المستوردة للموقع والبريد، خصوصًا A وAAAA وMX وTXT. احتفظ بنسخة من سجلاتك قبل تغيير Nameservers.
3. من Hostinger افتح Domains ثم الدومين ثم DNS / Nameservers، واختر تعديل Nameservers. أدخل القيمتين المخصصتين لهذا الدومين في Cloudflare؛ البرنامج يعرضهما بعد الاتصال. انتظر حتى تصبح حالة الدومين Active.
4. من [API Tokens](https://dash.cloudflare.com/profile/api-tokens) أنشئ Custom Token بصلاحيات `Zone / Zone / Read` و`Zone / DNS / Edit` للدومين المطلوب، و`Account / Cloudflare Tunnel / Edit` للحساب المطلوب. قد يظهر الاسم الجديد `Cloudflare One Connector: cloudflared / Write`. لا ترسل التوكن في الشات؛ أدخله في البرنامج فقط.
5. في البرنامج اكتب اسم العميل والدومين `daisson.tech`، ثم API Token واضغط «اتصال وحفظ». اختر نفقًا موجودًا أو اكتب اسمًا واضغط «إنشاء نفق جديد».
6. تبويب البرامج يكتشف ملفات `SERVER_INFO.txt` ومديري السيرفرات. افحص مجلد تثبيت آخر إذا لم يظهر برنامج. يمكن إضافة أي خدمة HTTP يدويًا على `localhost` أو `127.0.0.1` أو `::1`.
7. أمثلة المسارات: `sunday` → `http://127.0.0.1:5050`، و`membership` → `http://127.0.0.1:5060`. النتيجة `https://sunday.daisson.tech` و`https://membership.daisson.tech`. كل برنامج يمكنه استخدام منفذ مختلف على نفس النفق. لا تختَر منافذ PostgreSQL.
8. اضبط مصادقة API وصلاحياته قبل تفعيل «API محمي» و«نشر». هذه الخانة تأكيد منك وليست فحص اختراق آليًا. **التثبيت الحالي للعضوية على 5060 يحتاج مصادقة API فعلية، ومدارس الأحد تحتاج Jwt:Secret خاصًا قبل النشر العام.** لا تنشرهما بإعداداتهما غير المحمية.
9. اضغط «مراجعة DNS والمسارات». راجع الروابط ثم «تنفيذ المراجعة المعروضة». البرنامج يرفض DNS أو المسارات المتعارضة ويحافظ على الإعدادات الأخرى. تغيير الإعدادات يلغي المراجعة السابقة.
10. إذا كان للنفق موصل يعمل في خدمة Cloudflared الحالية، يكفي نشر المسارات. إن لم يكن له موصل، اختر «تنزيل وتثبيت موصل العميل كخدمة» ووافق على UAC. يتم تنزيل cloudflared الرسمي والتحقق من SHA256 ثم إنشاء خدمة `DaissonTunnelConnector` مستقلة.
11. أعد «اتصال وحفظ» للتحقق من حالة النفق. حالة خدمة ويندوز «تعمل» وحدها لا تثبت اتصال Cloudflare. انتظر Healthy ثم اختبر HTTPS من بيانات الموبايل. افتح مدير كل سيرفر مع ويندوز؛ الموصل لا يشغّل قاعدة البيانات أو سيرفر التطبيق.

## الزباين والدومينات المختلفة

- «عميل جديد» ينشئ ملفًا مستقلًا. أدخل دومين الزبون وحسابه وتوكنه واختر نفقه؛ يمكن استخدام نفس السب دومين مثل `app` مع دومين مختلف لكل زبون.
- على جهاز واحد، يمكن لخدمة Daisson تشغيل عدة أنفاق. تبديل العميل في الواجهة لا يوقف العملاء الآخرين. إضافة أو إزالة موصل تعيد تشغيل **خدمة Daisson فقط** لتطبيق القائمة الجديدة، وقد تقطع اتصالات عملائها لثوانٍ. خدمة Cloudflared القديمة لا تتغير.
- إذا كانت سيرفرات الزبائن على أجهزة مختلفة، ثبّت البرنامج والموصل المناسب على كل جهاز. `127.0.0.1` يشير إلى الجهاز الذي يعمل عليه الموصل؛ ملف العميل لا يحوّل جهازك إلى سيرفر لجهاز زبون آخر.
- التصدير ينقل الاسم والدومين والمسارات والملاحظات فقط، بدون توكنات أو حساب/نفق أو مسارات تشغيل الملفات. الاستيراد ينشئ هوية عميل جديدة ويجعل النشر والحماية غير محددين، لتراجع الإعدادات على الجهاز الآخر.
- تغيير الدومين يفصل اختيار الحساب والنفق السابق. حذف سطر محلي لا يحذف DNS أو المسار المنشور؛ احذف المسار والسجل المطلوبين من Cloudflare عند الحاجة.

## التخزين والخدمات

- ملفات العملاء ونسخ الإعدادات السابقة مشفرة بـWindows DPAPI لحساب ويندوز الحالي في `%LocalAppData%\DaissonTunnelManager`. لا يمكن نقلها لحساب آخر مباشرة؛ استخدم التصدير ثم أعد إدخال التوكنات. لا يُكتب التوكن في سطر أوامر خدمة ويندوز.
- ملف موصلات الخدمة في `%ProgramData%\DaissonTunnelManager\connectors.bin` مشفر للجهاز، ومجلده مقصور على SYSTEM وAdministrators. ملفات الخدمة في `%ProgramFiles%\Daisson Tunnel Manager\Service`. تغيير صلاحيات هذه المجلدات يضعف حماية الأسرار.
- عند تثبيت موصل استخدم UAC لنفس حساب ويندوز. إن استخدمت حساب مسؤول مختلفًا، افتح البرنامج بذلك الحساب وأدخل بيانات العميل هناك لأن طلب التثبيت مشفر لحساب المستخدم.
- سجل الخدمة مقصور على حالة بدء/خروج عمليات الموصل دون حفظ مخرجات cloudflared التي قد تحتوي أسرارًا. مساره `%ProgramData%\DaissonTunnelManager\service.log`.
- زر إزالة موصل العميل يفصله من خدمة Daisson فقط. لا يحذف النفق أو DNS. إيقاف خدمة Daisson يوقف موصلات كل عملائها على الجهاز. إزالة واجهة البرنامج من ويندوز لا تحذف خدمة مستقلة قد يستخدمها عملاء آخرون؛ أزل الموصلات ثم أوقف الخدمة قبل الاستغناء عن الجهاز.
- قبل تنفيذ المسارات تُحفظ نسخة Cloudflare السابقة مشفرة في `backups`. عند الفشل يحاول البرنامج التراجع عن التغييرات المؤكدة. إذا انقطع الاتصال أثناء إنشاء DNS، أو تغيرت الإعدادات من جهة أخرى، قد يلزم مراجعة اللوحة يدويًا؛ لا يتم الكتابة فوق تغيير خارجي لأجل التراجع.

## ما تم اختباره وما يحتاج حسابك

اختبارات محلية: دومينات مختلفة، منع نقل توكنات أو مسارات تنفيذ عبر الاستيراد، تشفير الملفات، تعارضات DNS، حفظ المسارات والخيارات القديمة، رفض مراجعة قديمة أو لعميل مختلف، التراجع عند فشل DNS، تشغيل عملية موصل فرعية وإيقافها، اكتشاف المنافذ من بيانات التثبيت، اتصالات HTTP، وفتح وإغلاق واجهة ويندوز.

اختبارات Cloudflare استخدمت API وهمية دون تعديل حساب حقيقي. لم يتم تثبيت خدمة جديدة على الجهاز الحالي أو تغيير Nameservers أو نشر السيرفرات. تثبيت الخدمة الفعلي ونجاح رابط عام يحتاجان UAC وAPI Token وتفعيل الدومين ومصادقة السيرفر.

## البناء من المصدر

```powershell
dotnet run --project Tests/DaissonTunnelManager.Tests.csproj -c Release
dotnet publish DaissonTunnelManager.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=None -o publish
```

ابنِ ملف التثبيت باستخدام `installer.iss` بعد النشر. لا يحتاج المشروع حزم NuGet خارج إطار .NET.
