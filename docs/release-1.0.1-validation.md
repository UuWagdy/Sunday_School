# تقرير إصلاحات وإصدار 1.0.1+2

التاريخ: 2026-10-17. العمل على نسخة المشروع الحالية مع الحفاظ على التعديلات الموجودة سابقًا. لم تُستخدم قاعدة المستخدم في الاختبارات ولم يُثبت إصدار على جهازه.

## النتيجة الوظيفية

- اقتراح أسماء أشخاص مشابهة أثناء كتابة الاسم، بعد مهلة 250ms، مع تطبيع اختلافات العربية. الاقتراحات ضمن نطاق المستخدم؛ يمكن عرض ملخص للشخص الموجود دون استبدال مسودة الشخص الجديد. الأسماء المتشابهة لا تمنع الحفظ قسرًا لأن شخصين قد يشتركان في الاسم.
- إصلاح ربط الخدمات في المراحل والخوارس والتعديل الجماعي. حفظ السجل والروابط وتحديث روابط الأعضاء داخل معاملة واحدة، مع إشعارات Drift. إصلاح ترجمة مقارنة SQLite ذات `IS NOT ?` إلى المقابل الصحيح في PostgreSQL، الذي كان يمنع تعديل المرحلة على السيرفر.
- إضافة «رؤية البيانات» في صلاحيات المستخدم: الخدمة، النوع، المرحلة، الخورس، المنطقة، الرهط، القائد. كل بند افتراضيًا «الكل». الاختيارات داخل البند OR، وبين البنود AND. إلغاء الكل دون اختيار قيم يعني عدم رؤية بيانات. المنطقة تشمل فروعها، والخدمة تشمل الربط المباشر والموروث من المرحلة/الخورس.
- مثال الخدمة أ + ذكر + 5ب يعرض المطابقين فقط. التقييد مركزي على القراءة، فيشمل القوائم والإحصائيات والحضور والطايو والأتوبيسات والأقارب والمستندات والتقارير وتصدير بيانات التبويبات. لا يوجد تغيير في schemaVersion 40؛ النطاق محفوظ في Settings لكل مستخدم.
- الصندوق والرهوط يستخدمان JSON؛ تُحجب الأعضاء/المدفوعات المخفية، ويُدمج حفظ المستخدم المحدود مع القيم المخفية للحفاظ عليها.
- النسخ الاحتياطي الكامل والاستعادة ومسح القاعدة تتطلب صلاحية الصيانة ورؤية كل البيانات. تصدير التبويب متاح لبيانات النطاق حسب صلاحياته. ضبط المصنع يحتفظ بنطاقات رؤية المستخدمين.

## نتائج مراجعة التحديث الصامت

| البند | المعالجة |
|---|---|
| أخطاء التجميع | تصحيح callbacks وسبب التحديث واسم domain واستيراد نوع المنطقة |
| إعادة إنشاء coordinator | إزالة إعادة تعيين late-final، وتنظيف الـinstance الصحيح عند تبديل المصدر |
| أول تحميل للأتوبيسات | لا قراءة لحالة Notifier قبل تهيئتها |
| وصول نتيجة بحث قديم | حماية generations قبل تطبيق النتائج في الشاشات ذات التحميل اليدوي |
| فقد تحديث معلق | الاحتفاظ بأحدث callback وتشغيله بعد انتهاء الجيل السابق |
| تداخل الصفحات | عزل الصفحة عن التحديث، وإعادة جلب النافذة المحملة، وحفظ offset الخام للحضور، ومنع تكرار الصفوف، ومفاتيح ثابتة |
| تحديث الأتوبيسات المكرر | مسار مجدول واحد وواجهة صامتة تحفظ الجدول؛ حماية السائق والتاريخ من النتائج المتأخرة |
| مبلغ الصندوق السنوي | التعيين البرمجي لا يعتبر تعديلًا؛ لا تُمسح حماية المسودة قبل نجاح حفظ نفس القيمة |
| اسم البرنامج المحلي | مراقبة settings revision وتحديث الهوية دون إعادة فتح الشاشة |
| تقرير طايو فارغ/نقاط الحضور | مراقبة Coming عند تضمين الحضور، وتحديث التقرير المنفذ حتى لو كان فارغًا |
| مقارنة الفترات | نسخة ثابتة من الفترات والأشخاص وخيار التجميع المنفذ |
| معاينة PDF | توليد من snapshot النتائج وحفظ Future والبايتات، ومنع نتيجة PDF القديمة من إحلال الأحدث |
| تقفيل الترم | طلبات متسلسلة مع تحديث معلق، ومعاملات حساب ثابتة وتصدير snapshot مستقل |
| قالب الكارنيه | snapshot إعدادات واحد، تحديث القالب النظيف، وحفظ المسودة مع تنبيه لتغيير خارجي وخيار تحميله |
| أخطاء التحديث | أخطاء القراءة تنتقل لآلية التحديث بدل اعتبارها قائمة فارغة ناجحة؛ الاحتفاظ بالنتيجة السابقة ومنع حلقات إعادة المحاولة |

تم نقل DataScopeBoundary فوق MaterialApp/Navigator ليشمل الحوارات أيضًا، مع اختبار إغلاق محرر النطاق القديم عند تغيير الرؤية. التغييرات العادية تحفظ حالة الشاشة والمسودات. تغيير المستخدم أو القاعدة أو نطاق الرؤية ينشئ حاوية بيانات جديدة حتى لا تظهر لقطة قديمة من نطاق أوسع. إعادة الاتصال واستئناف التطبيق تعيدان التحقق مع إخطار مراقبي Drift. اتصال SignalR ينتظر إقرار handshake ويعزل الاستجابات القادمة من اتصال سابق.

## حدود السيرفر وطريقة التطبيق

- Storage وSignalR يحتاجان JWT. يُقرأ نطاق المستخدم من قاعدة السيرفر في كل طلب؛ تعديل الصلاحيات يسري على الـtoken الحالي.
- التحقق يشمل read/insert/execute/batch والمعاملات. لا يستطيع المستخدم المحدود تعديل نطاقه بنفسه دون إدارة المستخدمين أو استخدام معاملة مستخدم آخر. شروط UPDATE المضافة لا يمكن تجاوزها بـOR.
- شاشة الدخول تستخدم قائمة أسماء عامة آمنة؛ لا تُنشر منها كلمات المرور أو نطاقات المستخدمين.
- يجب تحديث مكوّن السيرفر على الجهاز الرئيسي مع تحديث العملاء؛ السيرفر القديم لا يفرض القيود الجديدة. اختر مكوّن السيرفر في installer على الجهاز الرئيسي إذا كان هذا الجهاز يستضيفه.

## دليل التحقق

- 50 اختبار Flutter للميزة في 15 ملفًا محددًا: النطاق المركزي وواجهته، عزل caches، اقتراح الأسماء، ربط الخدمات، coordinator/domains/controller، اختبارات إعادة الإنتاج، الأتوبيسات والطايو والكارنيه والتنقل، وانتقال أخطاء القراءة.
- 28 اختبار توافق في 8 ملفات محددة: استحقاق الخدمات، قيود الحضور، درجات السلوك وتقفيل الترم، عرض الحضور، عقد الاستعلام البعيد، إعداد الاتصال، PDF وmigration الروابط.
- أُعيد تشغيل 8 اختبارات متأثرة بآخر تعديلات الحفظ والأتوبيسات ونجحت.
- `tool/test_visibility_server.py` ينشئ PostgreSQL وسيرفر HTTP مؤقتين على loopback بمنافذ مستقلة، ويغلق عملياته في finally. النتيجة العددية ومسار السجلات في `docs/server-visibility-test-result.json`.
- اختبار Flutter منفصل على نفس السيرفر المؤقت يمرر استعلامات repositories الحقيقية، ويربط الخدمات، ويتحقق من وصول SignalR لتغيير أرسله عميل ثانٍ.
- الفحص الساكن محدود لملفات محددة فقط. لم يُشغل `flutter analyze`. يوجد في الشاشات القديمة تنبيهات style/deprecation؛ ليست إعلانًا عن خلو المشروع كله من التنبيهات.
- fixture اختبار migration مختصرة وتطبع تحذيرات عن جداول لم ينشئها الاختبار؛ assertions الخاصة بترحيل الروابط نجحت. هذه ليست قاعدة المستخدم.
