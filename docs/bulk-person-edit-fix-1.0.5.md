# إصلاح التعديل الجماعي واختيار عدد الأشخاص — 1.0.5+5

## السبب

تجربة الواجهة الكاملة على مخدومين وأربع خدمات أعادت إنتاج الخطأ:

```text
type 'Value<dynamic>' is not a subtype of type 'Value<int?>'
_PersonsScreenState._bulkEditSelected
```

نافذة التعديل كانت تُرجع Map<String, dynamic>. الحقول غير المحددة للتعديل كانت تحمل Value<dynamic>. عند تمريرها إلى المستودع الذي ينتظر Value<int?> أو Value<String?>، يحدث الخطأ قبل تنفيذ الحفظ؛ اختبارات المستودع التي تمرر الأنواع الصحيحة مباشرة لم تكن تكشف ذلك.

## الإصلاح

- استبدال النتيجة الديناميكية بنموذج BulkPersonEdit ذي حقول محددة الأنواع، مع الحفاظ على الفرق بين عدم تعديل الحقل ومسح قيمته.
- التقاط أرقام المخدومين المحددين قبل فتح النافذة، ليظل الحفظ موجّهًا لنفس الأشخاص إذا وصلت تحديثات أثناء فتحها.
- إصلاح أزرار عدد الأشخاص؛ كان النص فارغًا لكل الأرقام، وأصبح يعرض 50 / 100 / 200 / 500 / الكل.

## اختبار الواجهة

الاختبار يستخدم شاشات PersonsScreen وBulkEditDialog وPersonDialog الفعلية ومستودع الحفظ الفعلي. يحدد اثنين من ثلاثة مخدومين، يختار أربع خدمات بالضغط على عناصر الاختيار، يحفظ، ثم يفتح بيانات كل مخدوم ونافذة خدماته ويتحقق من تحديد الخدمات الأربع. يتحقق أيضًا من عدم تغيير المخدوم الثالث أو أرقام التليفونات. يوجد فحص مستقل لظهور أرقام التحميل واختيار 500 في الوضعين الفاتح والغامق.

يمكن تشغيله محليًا:

```powershell
flutter test --no-pub test/bulk_person_services_widget_test.dart
```

ولتشغيله عبر HTTP وقاعدة PostgreSQL مؤقتة مع اختبارات الخدمات:

```powershell
python tool/test_service_assignments.py
```

بيانات الاختبار مصطنعة. لا يستخدم المشغّل قاعدة المستخدم. لا يوجد تغيير في مخطط قاعدة البيانات.
