## قواعد لا يجوز مخالفتها

1. ممنوع تشغيل `flutter analyze` إطلاقًا، مباشرة أو من سكربت أو وكيل، وممنوع أي whole-project analyzer بديل. للتحقق استخدم اختبارات Flutter محددة الملفات، و`dart analyze` لملفات معدلة محددة فقط إذا احتجته فعلًا.
2. توجد تغييرات محلية سابقة كثيرة وملفات غير متتبعة، منها السيرفر والمزامنة. احفظ baseline قابلة للمقارنة قبل التنفيذ، وتتبع ما عدلته أنت. لا تعمل reset/clean أو تلغِ عمل المستخدم أو تعتبر كل diff شغلك.
3. لا commit/push/deploy، ولا تشغيل تعديلات تجريبية على بيانات المستخدم الحقيقية. لا إعادة تصميم أو schema/backend migration أو تبديل stack إلا لضرورة مثبتة ضمن المهمة ومذكورة بالتقرير.
4. أكمل نطاق الشاشات والمكونات والحوارات والتبويبات الداخلية؛ لا تنتهِ عند إصلاح الأشخاص والحضور فقط. حصر الخطة 27 ملف شاشة ويجب مطابقته بالحصر الفعلي.
5. لا تستخدم polling دوريًا أو `UniqueKey` أو إعادة إنشاء الشاشات/ProviderScope/قاعدة البيانات لإجبار refresh.
6. لا تجعل إشعار المزامنة ينفذ save/delete/transfer/print أو يعيد توليد الرهوط أو تشغيل الكاميرا.
7. إذا واجهت مانعًا حقيقيًا، سجل ما أُنجز وما بقي والأثر على القبول بوضوح، ولا تدّعِ اكتمال ما لم تنفذه أو تختبره. إذا فرضت تعليمات المستودع توقفًا مرحليًا، احترمه ووضح الجزء المتبقي.

## طريقة العمل المطلوبة

- أنشئ تقرير التنفيذ مبكرًا وحدّثه مع العمل، بمصفوفة تغطية لكل شاشة ومكون بيانات.
- استفد من SignalR وDrift وRiverpod الحاليين، واجعل لكل نتيجة عرض مالك refresh واحدًا وتبعيات جداول صحيحة.
- غطِّ SQLite المحلي والسيرفر، وتغير المراجع والروابط والحقول وSettings، وreconnect/resume والصلاحيات.
- افصل أول تحميل عن background revalidation، واحتفظ بآخر snapshot صحيحة حتى اكتمال الجديدة، بما فيها القائمة الفارغة.
- نفّذ single-flight وpending وquery snapshot/generation وsource/session epoch، مع debounce محدود الانتظار ومنع النتائج القديمة من استبدال الجديدة.
- احفظ نافذة pagination وحل load-more المتزامن، وIDs التحديد ومفاتيح الصفوف والتمرير، ولا ترجع للصفحة الأولى لكل حدث.
- افصل draft المستخدم عن بيانات السيرفر، خصوصًا السلوك والصندوق والرهوط ومصمم الكارنيهات وPersonDialog ونماذج الإدارة. اكشف التعارض المعروف دون overwrite صامت، ولا تعد بضمان atomic concurrency لا تدعمه API الحالية.
- في التقارير جدّد آخر query منفذة، لا draft filters غير المنفذة، وامنع توليد PDF لكل build أو تكرار الطباعة.
- قدم تحديثات مختصرة عن التقدم، واختبر النمط المشترك أولًا ثم عممه؛ لا تنسخ مسارًا لم يثبت حفظ الحالة.
- شغّل الاختبارات المركزة المناسبة فعلًا، وراجع diff، ونسق الملفات التي عدلتها لهذه المهمة فقط.
